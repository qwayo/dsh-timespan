# 历史任务回填：重放已持久化会话事件

状态：accepted
日期：2026-11-04

票 05 让统计覆盖插件启用之前的时间。回填不是另写一套任务算法，而是把 `sessionQuery.readSession()` 读到的历史事件流喂给实时 `session/event` 用的同一个归约器（`applySessionEvent`），只是把每条任务标成 `source: 'backfill'`。这样任务时长、任务构成、审批等待、异常收口等语义始终只有一份定义，实时与历史不会随时间漂移。

只重放「已完成」的 turn：扫描事件流里的 `turn/end`（含日志修复补出的 interrupted/forked 收口事件），再保留这些 turn 的结构性事件与 `session/title`。回填范围内仍在进行中的 turn 不产出任务，因为它没有确定的结束时刻；这与父规格 00 的「崩溃恢复时把未结束任务按最后一次事件时间收口并标记中断」是两条不同的路径，后者只处理插件自己记录的实时任务，本决策不改写它。`session/title` 与 `cwd` 分别给出会话标题与工作区归属，工作区解析复用实时记录的那套逻辑。

边界处理遵循会话日志本身的语义：fork 会话用 `readSession()` 给出的 `inheritedEventCount` 按数组位置切掉继承前缀（它是前缀的事件数量、即数组切点下标，与事件的 `seq` 值无关）；标题派生与收口时间同样只取自身事件，父会话的事件不属于子会话，不能重复计一次。子代理会话照常写入 `tasks` 原始明细并带 `origin: 'subagent'` / `parentSessionId`，但总计、工作区与会话列表沿用 ADR-0002 的顶层过滤，不重复计入；仪表盘响应额外按 `parentSessionId` 附带一份子代理摘要，使票 05 的「可在父会话明细中看到」成立。Host 只扫描 `persisted && !live` 的会话：仍在运行的会话由实时事件记录，重放它的历史 turn 会误伤当前正在累积的实时任务。

幂等与进度放在同一份 `meta.backfill` 里：任务键是 `sessionId:turn`，重放重复事件不会新增记录；状态为 `done` **且算法版本一致**时才短路，`force: true` 或版本升级都会重扫，因此「重复启动不重复计数」不会退化成「算法升级后永不补扫」。失败记为 `failed`，页面可点「重试」触发一次强制重跑。回填只补任务时长，不伪造启用前的在线/活跃区间：按 ADR-0001，在线由 Host 进程生命周期记录、活跃由 Client 心跳推导，两者都是插件启用后的实时观测，历史日志没有可信来源。

后台执行不阻塞实时记录：Host 不设固定启动延时，而是在客户端第一次 `queryStats` / `presence` 时由 RPC 兜底触发，此时组合里的 `sessionQuery` 已挂载完毕，避免「服务还没就绪就扫到空列表并永久记为 done」。不 `await` 回填；`listSessions()` 只列目录，`readSession()` 以带 `load()` 的延迟条目逐个解压，进度在开始时就有准确的 `total`。每个会话之间让出一次宏任务，实时事件与心跳可以插队。所有外部写入统一走领域服务的写锁，回填的每个事件各自加锁而不是整次独占，避免长任务把心跳挂住；`turn/start` 引发的历史任务收口也只作用于 `source: 'backfill'` 的开放任务。逐事件重放的中间态会短暂出现「只有 `turn/start`、没有 `turn/end`」的开放任务，若被查询看到会被当成从历史起点运行到当前的巨型任务，因此这类开放回填任务在投影阶段一律跳过，等会话重放结束按日志时间收口后才进入统计（同时也是回填中断到重试之间的失败路径保护）。

考虑过的替代方案：直接按 `turn/start` / `turn/end` 时间戳预生成任务记录会绕开归约器，导致历史与实时的任务构成口径分叉，后续每次规则调整都要改两处；把回填整次包进一个写事务会阻塞实时写入；把进度另存文件会与 `meta` 的安装时/启动次信息脱节。代价是回填期间要逐事件写库、并需要在投影层识别半成品任务，但会话数是本地量级，且完成状态后不再重跑。
