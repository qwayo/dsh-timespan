# ⓘ 说明浮层从点击 popover 反转回悬浮/聚焦触发

`DESIGN.md` 曾把 ⓘ 说明定为「点击展开的 popover，禁用悬停与键盘聚焦」，并在 #1 / #2 里由用户确认固化。2026-11-08 用户要求「感叹号图标现在是点击触发，我希望你把它弄成鼠标悬浮触发，而且你触发的位置的那个小字描述应该是紧贴这个图标下。并且要保证显示不出错，也就是说如果这个感叹号图标处于边缘的话，那么它显示的小字应该是不会被遮挡住的」。这是对一条已确认设计约束的刻意反转，不是回归。

决定：ⓘ 改回 `onMouseEnter` / `onFocus` 显示、`onMouseLeave` / `onBlur` 隐藏；浮层默认紧贴图标下方 4px，底部空间不足时翻到上方，水平按视口夹取（margin 8px）；去掉点击 toggle、`aria-expanded` 与 document 级 pointerdown 外部关闭，Esc 仍关闭当前浮层。保留 `position: fixed`、z-index 90、`pointer-events: none` 与共享 `clampTipPosition`；`viewIn` / `viewOut` / `cs-focus-in` 只动 opacity，避免 transform 让祖先成为 fixed 浮层的包含块，否则边缘浮层会被裁切。五处下拉菜单同理改为 fixed + 视口夹取，不引入 `ReactDOM.createPortal`。

替代方案（保留点击、只把浮层挪到图标下方）不能同时满足「悬浮触发」与「紧贴图标下」；保留 CSS `:hover` 但继续用点击 toggle 会让两种触发语义打架，且键盘聚焦与 Esc 语义难以自洽。代价是纯触屏设备没有悬浮态，键盘用户仍靠 focus 触发；`client-composition.test.js` 里旧的「点击展开 / 禁用 `:hover`」断言同步反转，`DESIGN.md` 第 33 行与相关口径同步改写。
