# 使用时长采集采用 Host 事件 + Client 前台心跳

状态：accepted
日期：2026-11-04

dsh-timespan 要记录在线、活跃、任务三类时间。在线与任务只有 Host 能看到（进程生命周期、`session/event` 的 turn 边界），但「用户此刻在看哪个会话」只有 Web 客户端知道。因此插件必须双端：Host 记录在线心跳与会话事件并持久化；Client 每 15 秒上报可见性、聚焦状态、前台会话和最近操作时间，活跃区间只能由客户端心跳推导。原始区间保留在本地 `storageDomain`，日/周/月只是查询时派生视图，调整时区或周起始后可以重算历史；空闲阈值修改只影响之后的活跃判定，已落库的历史活跃区间不重算。

考虑过的替代方案：纯 Host 采集无法把使用时间归属到会话；纯 Client 采集在页面关闭后丢失在线时间，也看不到任务事件；只存日汇总会让口径变化无法回退。代价是插件有两个半端、活跃数据依赖客户端在线，并且活跃精度受 15 秒心跳限制。
