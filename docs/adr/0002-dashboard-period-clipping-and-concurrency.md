# 仪表盘的周期裁剪与两种统计口径

状态：accepted
日期：2026-11-04

票 04 把日/周/月仪表盘建立在 ADR-0001 的「原始区间 + 查询时派生视图」之上。周期边界由 Host 侧的纯函数按本地时区派生（日从 00:00、周从周一 00:00、月从 1 日 00:00），上界一律截到当前时刻；用 `new Date(y, m, d, h)` 逐日逐时构造，而不是在时间戳上加减固定毫秒，避免夏令时切换日偏移。周起始保留可配置参数，默认周一。

原始区间在查询时按窗口裁剪，因此一条跨午夜、跨周或跨月的区间会自然分到相邻周期，各周期只计入落在自己窗口内的部分；不需要在采集侧预先切分，也不会因为口径变化而丢失历史。趋势图按「当前周期内的自然子区间」分桶（日按小时、周按天、月按天），桶之间互不重叠，可以直接相加回总览数字。

并发数据同时提供两种口径：总览的活跃时长与任务时长按时间并集（实际占用），工作区→会话明细按会话求和（累计工时）。两者都从同一批投影区间与任务行派生，页面分别标注，避免把「明细之和」误读成「总览主数字」。领域服务保留 `tasks` 原始明细（含子代理记录）供后续面板使用，但所有总计与页面上的工作区/会话明细都基于过滤掉子代理的顶层任务；私有 RPC 不向 Client 暴露 `tasks`。只有活跃、没有任务的会话也会出现在明细里。

考虑过的替代方案：把周期边界与桶放在 Client 计算，会让页面持有业务规则且难以与 `chrono_stats` 工具保持一致；采集时按日预聚合会让跨午夜切分与周起始调整无法回退。代价是一次 dashboard 查询要遍历多个桶，但数据量是本地区间级，开销可接受。
